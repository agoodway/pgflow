# Upstream pgflow 0.17.2 Schema Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship core **V03** and helpers **V07** so that an Elixir-installed `pgflow` schema is identical to upstream `pgflow@0.17.2` (`baa9e43f5f9122133deacbc3e8ffc80e284b4f50`), apart from documented overlays. Apply them with a stop-and-drain upgrade. The result is that TypeScript 0.17.2 workers and Elixir OTP workers can share one database in flow mode.

**Architecture:** Core V03 is generated by the existing reproducible importer (`mix pgflow.sync_upstream`). It is a recorded delta from the V02 state, and its manifest lists every transformation. Helpers V07 re-applies the Elixir overlays: the 8-column claim record and a versioned `register_worker`. The Elixir runtime changes only in four places:

- its SQL call sites;
- its schema gate;
- new guardrails: `PgFlow.Slug` rules, DSL compile-time validation, `mix pgflow.audit_slugs`, and a versioned upgrade wrapper;
- the acceptance gate, which is the upstream harness (catalog diff, pgTAP, real TS workers) plus the demo app.

**Tech Stack:**
- Elixir ~> 1.18 (`.tool-versions`: elixir 1.19.1-otp-28, erlang 28.1.1), Ecto/Postgrex
- EctoEvolver 0.1.0 (unchanged)
- PostgreSQL 17 + PGMQ + pg_cron (image `jumski/atlas-postgres-pgflow:17.6.1.054`), pgTAP
- Upstream harness: Node 22, pnpm 10.20.0, supabase CLI 2.117.0
- Phoenix 1.8 demo, ExUnit

**Design spec:** [2026-10-30-upstream-0-17-schema-parity-design.md](../specs/2026-10-30-upstream-0-17-schema-parity-design.md). Read it first. It inlines the gap analysis, explains why expand/contract was rejected, and gives the upgrade procedure.

**Verified against:** `agoodway/pgflow` `main` @ `3770b0d` and `pgflow-dev/pgflow` tag `pgflow@0.17.2` @ `baa9e43f`. All paths and line references below were checked against those revisions; line numbers are approximate anchors and the quoted code is authoritative.

## Why stop-and-drain, not an Oban-style rolling upgrade

Oban's `Oban.Migrations.Postgres.VNN` steps are additive. Oban owns both its job table and its queries, so old and new nodes can overlap. pgflow 0.17 is not additive:

- it drops the 4-arg `start_tasks` and the 2-arg `ensure_flow_compiled`
- it tightens `slug_is_valid`
- it changes PGMQ routing

Upstream states there is no rolling mixed-version upgrade. A bridge would need ambiguous overloads and a catalog that never equals 0.17.2. We keep only Oban's discipline: numbered, forward-only, transactional versions; one wrapper that runs core then helpers; and a boot-time version check. Full rationale: spec §2.1.

## Global constraints

- **No expand/contract, no dual schema, no rolling upgrade.** Ship one core V03 and one helpers V07, applied inside a single Ecto migration transaction during a stop-and-drain window.
- **The parity target is the released tag `pgflow@0.17.2` (`baa9e43f`)**, not upstream `main`. Do not import #708 (falsy outputs; 0.17.3 is pending in #709).
- **Do not modify published SQL.** Core V01/V02 and helpers V01–V06 bytes stay frozen. After this plan, `@published_versions` is `["01", "02"]`.
- **Do not change the `ecto_evolver` dependency** (<https://github.com/agoodway/ecto_evolver>). Adapt `mix pgflow.setup --upgrade` instead.
- **pgflow never renames or re-cases slugs.** If legacy data is invalid, V03 fails atomically and reports it.
- **Out of scope:** an Elixir step-mode worker or per-step queue polling (possible future phase), the `pgflow_telemetry` schema and its pg_cron/pg_net jobs, and `ensure_workers` / Supabase edge-function plumbing.
- **Idiomatic OTP.** No new processes and no supervision changes. Do not port the TS worker structure. Database transactions own correctness; notifications only make polling faster.
- **TDD per task:** write a failing test, run it and watch it fail for the expected reason, implement the minimum, run it and watch it pass, run the related suites, then commit.
- **Migration tests** (`@moduletag :migration`) drop schemas. Run them separately with `PGFLOW_REQUIRE_DB=1 mix test --only migration`, never in parallel with the main suite.
- **No secrets in files, commits or logs.** The only credentials in this plan are the throwaway local test-container ones already committed in `test/support/db/compose.yaml`, `config/test.exs` and `demo/config/test.exs`. The demo's LLM key (`demo/.env`) is never needed; baseline scenarios require no network or credentials.
- **Execution ledger:** append each task's RED/GREEN evidence to "Execution ledger" at the end of this file, the way the 2026-09-14 plans do. Check a box only after its evidence exists.

## Commit conventions

These conventions match `git log main` (last 50 commits, up to `3770b0d`).

- **Subject:** `<type>: <Capitalized imperative summary>`, with no scope in parentheses and no trailing period, at most about 70 characters. Types in use: `feat`, `fix`, `test`, `docs`, `chore`, `refactor`, `style`. Examples from main:
  - `feat: Escalate permanently stalled tasks`
  - `fix: Detach upstream fixture repositories`
  - `test: Abort when the test DB helpers version is stale`
  - `chore: Bump package version to 0.4.0`
  - `docs: Document conditional steps and delivery guarantees`
- **Body** (when the change is not trivial): a blank line, then 2–5 `- ` bullets in the same imperative, capitalized voice. For example:

```
feat: Escalate permanently stalled tasks

- Add helpers V06 recovery and step progress view
- Upgrade the demo schema and local package integration
- Cover stall escalation, migrations, and worker behavior
```

- Commit once per task on the work branch, using the subject given in each task. Add bullets describing what actually changed. Do not add `Co-authored-by`, issue-closing keywords, or scopes.
- **Version bumps** are their own `chore:` commit (`chore: Bump package version to 0.6.0`), as `d48fbae` did.
- Do not push to `main`, force-push, or open PRs unless the human asks. Pushing the agent's own work branch is allowed when the operator configured that.

defmodule PgFlow.Slug do
  @moduledoc """
  Upstream pgflow 0.17.2 slug rules (`pgflow.is_valid_slug/1`), mirrored for
  compile-time and pre-flight checks. The database remains authoritative.
  """

  @max_slug_length 128
  @max_queue_name_length 47
  @reserved ~w(run)

  @type reason ::
          :empty | :too_long | :bad_chars | :reserved | :bad_start | :bad_end | :double_underscore

  @spec max_slug_length() :: pos_integer()
  def max_slug_length, do: @max_slug_length

  @spec max_queue_name_length() :: pos_integer()
  def max_queue_name_length, do: @max_queue_name_length

  @spec valid?(String.t() | atom()) :: boolean()
  def valid?(slug), do: validate(slug) == :ok

  @spec validate(String.t() | atom()) :: :ok | {:error, reason()}
  def validate(slug) when is_atom(slug), do: validate(Atom.to_string(slug))
  def validate(""), do: {:error, :empty}

  def validate(slug) when is_binary(slug) do
    cond do
      String.length(slug) > @max_slug_length -> {:error, :too_long}
      not Regex.match?(~r/\A[a-zA-Z_][a-zA-Z0-9_]*\z/, slug) -> {:error, :bad_chars}
      slug in @reserved -> {:error, :reserved}
      not Regex.match?(~r/\A[a-zA-Z]/, slug) -> {:error, :bad_start}
      not Regex.match?(~r/[a-zA-Z0-9]\z/, slug) -> {:error, :bad_end}
      String.contains?(slug, "__") -> {:error, :double_underscore}
      true -> :ok
    end
  end

  @spec queue_name(String.t() | atom()) :: String.t()
  def queue_name(slug) when is_atom(slug), do: queue_name(Atom.to_string(slug))
  def queue_name(slug) when is_binary(slug), do: String.downcase(slug)

  @spec validate_queue_name(String.t()) :: :ok | {:error, :queue_name_too_long}
  def validate_queue_name(name) when byte_size(name) <= @max_queue_name_length, do: :ok
  def validate_queue_name(_name), do: {:error, :queue_name_too_long}

  @spec describe(reason() | :queue_name_too_long) :: String.t()
  def describe(:empty), do: "must not be empty"
  def describe(:too_long), do: "must be at most #{@max_slug_length} characters"
  def describe(:bad_chars), do: "must match ^[a-zA-Z_][a-zA-Z0-9_]*$"
  def describe(:reserved), do: "\"run\" is reserved"
  def describe(:bad_start), do: "must start with a letter"
  def describe(:bad_end), do: "must end with a letter or digit"
  def describe(:double_underscore), do: "must not contain \"__\" (reserved for pgflow queue names)"

  def describe(:queue_name_too_long),
    do: "lower(flow_slug) is the PGMQ queue name and must be at most #{@max_queue_name_length} characters"
end
