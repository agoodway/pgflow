# Job Demo Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a homepage **Job** tab that enqueues a canned fake send-email job, shows highlighted `use PgFlow.Job` source, and displays the handler output when the run completes.

**Architecture:** New `PgflowDemo.Jobs.SendEmail` registered next to `ArticleFlowCleanup`. `FlowDemoLive` treats `:job` like `:cron` (no `switch_flow/2`). Layout B: Start Job + status, Job DSL, Output. Start calls `Client.enqueue/2`; subscribe + `reconcile_run_state/2` stay as they are. No library changes.

**Tech Stack:** Elixir, Phoenix LiveView, PgFlow (`use PgFlow.Job`, `Client.enqueue/2`), Makeup, ExUnit (`PgflowDemoWeb.ConnCase`).

**Spec:** `docs/superpowers/specs/2026-08-22-job-demo-design.md`

## Global Constraints

- Tab order: Article · Onboarding · Approval · **Job** · Cron.
- Tab label is **Job**. Selecting Job or Cron only assigns `selected_flow` — do not call `switch_flow/2`.
- Canned enqueue input is exactly `%{"to" => "demo@pgflow.dev", "subject" => "Welcome to PgFlow", "body" => "This email was enqueued as a Job."}`.
- No DAG, event log, Flow DSL, or step-output panel on the Job tab.
- No mailer, form fields, fail/retry UI, `/job` route, or dashboard code changes.
- Call `Client.enqueue/2` at the start site (do not call `start_flow/2` even though enqueue delegates).
- Do not boot `Worker.Server` inside `demo/` tests. Use synthetic `{:pgflow, run_id, event}` messages.
- Follow the Cron tab pattern already in `FlowDemoLive`.
- Demo Mix commands run from `demo/` (`cd demo && mix test …`).

defmodule PgflowDemo.Jobs.SendEmail do
  @moduledoc """
  One-off demo job. No mailer — returns a sent map so the homepage can
  teach `PgFlow.enqueue/2` and `use PgFlow.Job`.
  """
  use PgFlow.Job

  @job queue: :send_email, max_attempts: 3, timeout: 30

  perform :deliver do
    fn input, _ctx ->
      %{
        "sent" => true,
        "to" => input["to"],
        "subject" => input["subject"]
      }
    end
  end
end

```elixir
defp start_selected_job(socket) do
  case Client.enqueue(PgflowDemo.Jobs.SendEmail, @send_email_input) do
    {:ok, run_id} ->
      socket = cleanup_subscription(socket)
      Phoenix.PubSub.subscribe(PgflowDemo.PubSub, "pgflow:run:#{run_id}")
      cancel_timer(socket.assigns.timer_ref)

      socket =
        socket
        |> assign(:run_id, run_id)
        |> assign(:run_status, :running)
        |> assign(:error, nil)
        |> assign(:error_step, nil)
        |> assign(:step_outputs, %{})
        |> assign(:duration, nil)
        |> assign(:start_time, System.monotonic_time(:millisecond))
        |> assign(:elapsed_ms, 0)
        |> assign(:event_log, [
          log_entry(:info, "Job started", "Run ID: #{short_id(run_id)}")
        ])
        |> assign(:active_edges, MapSet.new())
        |> assign(:timer_ref, nil)
        |> assign(:output_step, nil)
        |> assign(:output_content, nil)
        |> assign(:output_loading, false)
        |> reconcile_run_state(run_id)

      timer_ref =
        if socket.assigns.run_status == :running, do: maybe_start_tick_timer(socket)

      {:noreply, assign(socket, :timer_ref, timer_ref)}

    {:error, reason} ->
      {:noreply, assign(socket, :error, format_user_error(reason))}
  end
end
```
